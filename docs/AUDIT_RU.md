## А. Оценка исходного проекта

Для небольшого статического портфолио архитектура достаточна и понятна: React 18, TypeScript, Vite 6, Tailwind 3, Framer Motion; компоненты секций отделены от данных кейсов. Главная страница собирает первый экран, результаты, карьеру, кейсы, навыки и контакты. Сохраняются горизонтальная карусель опыта, фильтры карточек, модальные окна Radix Dialog, эффекты наведения и canvas-фон. Markdown-контент хранится в репозитории; отдельный backend отсутствует.

Маршрутизация ограничивается `/` и страницей NotFound. Основные переходы — якоря. Для направлений портфолио достаточно query-параметра; новые пути и новая система маршрутизации не потребовались. Параметры фильтра читаются как ограниченный набор значений и не используются как внешний адрес перехода.

Сборка исходной версии и проверки TypeScript проходили. В браузере исходная страница не давала runtime-ошибок на пяти проверенных ширинах. Данные маркетинговых кейсов типизированы, внешние кнопки защищены `rel`, Markdown не подключает обработчик произвольного HTML. Это хорошая база для локального развития.

Слабые места: дублированные ID, переполнение навигации на планшете, доступность взаимодействий по hover, тяжёлая начальная загрузка, сломанные SEO-ресурсы, шаблонная тестовая инфраструктура и устаревшие зависимости. `strict` отключён; `build` сам по себе не проверяет типы. В `App.tsx` остаются React Query provider и две системы toast, хотя страница не использует запросы и уведомления. Значительная часть стандартных shadcn-компонентов, `NavLink.tsx`, `use-mobile.tsx` и `App.css` не участвует в работающей странице. Они не удалялись.

Проверены дерево репозитория, конфигурации, workflow, исходные и подключённые данные, граф импортов, runtime-компоненты и хуки, публичные ресурсы, содержимое отслеживаемого `dist.zip`, внешние адреса, проверки сборки и пользовательские сценарии. Это не утверждение об исчерпывающей проверке всех возможных состояний неиспользуемой библиотеки UI.

## В. Что изменено и почему

1. **Навигация и доступность:** локальные обработчики и атрибуты исправляют подтверждённые недоступные состояния. В карусели добавлено только освобождение wheel на границе и возможность фокуса. Конструкция карточек и эффекты остаются прежними.
2. **AI-направление:** обязательное поле `category` расширяет существующий `PortfolioCase`; три текущих кейса отнесены к marketing. Две кнопки направлений используют тот же визуальный язык фильтров. Направление хранится в URL, теги сбрасываются при смене направления. Работают Back и reload. Неизвестное направление безопасно показывает все проекты.
3. **Прямые ссылки:** после принятия ветки доступны `/?direction=ai#cases` и `/?direction=marketing#cases`; локально эти адреса проверены. Новые пути на GitHub Pages не создавались.
4. **Позиционирование:** первый экран, короткая подпись в навигации, контакты, footer и метаданные последовательно связывают AI pet-проекты с базой в B2B/CRM/digital. Из описания AI-навыков убрано неподтверждённое ускорение «в разы», исправлено название Claude Code. Коммерческие AI-внедрения не приписаны.
5. **SEO и факты:** починены конкретные отсутствующие ресурсы; 5,29% получено арифметически; +27% снова обозначает заявки. Название, автор, `lang=ru`, контакты и реальные достижения сохранены.
6. **Производительность:** WebP создан без потери пикселей, а не с новой картинкой. Декодированные RGBA-массивы четырёх файлов полностью равны исходным PNG. Общий объём этих WebP — 4 768 194 байта вместо 6 994 069 (−31,8%). До прокрутки в локальном Chromium теперь загружается только портрет 1 450 462 байта; прежняя страница загружала все четыре PNG. Это измерение ресурсов, не оценка LCP на мобильной сети. Отдельный Markdown chunk — 156,68 КБ / 47,24 КБ gzip; общий JS не стал меньше, но первоначальная загрузка сократилась примерно на 17,9%.
7. **Безопасность инструментов:** Vite и router обновлены внутри текущей major-версии. Обновление Vitest до 5 обосновано удалением уязвимой цепочки Tinypool и исправлением предупреждений mocker. Проект использовал только один простой Vitest-тест; он проходит после обновления. Vite 6.4.4 и Node 24 соответствуют требованиям Vitest 5; для работы нужен Node 22.12+ (или поддерживаемая новая ветка). Workflow использует Node 22. Исправлен только браузерный тип таймера `ReturnType<typeof setTimeout>`; визуальная логика canvas не менялась.

На сайте проект явно обозначен workflow-прототипом с offline-проверкой. Production, экономия времени и реальные созданные задачи не заявляются. Для точного описания личного вклада в настройки/Code-узлы по-прежнему нужна отдельная фиксация; незафиксированные live-тесты не приписываются.

### AI-суфлёр — прототип по описанию автора

Название исправлено на **AI-суфлёр** во всех текущих материалах. По прямому уточнению Алёны он представлен в AI-разделе как прототип, реализация которого не верифицирована. Подтверждено описание: анализ контекста онлайн-разговора и варианты ответа; описанный вклад — пользовательские сценарии, работа с контекстом/запросами к LLM и проверка ответов.

Исходники, текущая работоспособность, интерфейс и получение контекста не подтверждены. Не добавлены захват аудио, speech-to-text, конкретная модель, real-time, интеграции с сервисами созвонов или метрики. Публичный JSON является карточкой описания, а не доказательством выполнения приложения; обложка — схема идеи. Это не кейс готового продукта.

## Ж. Следующие шаги по приоритету

1. Просмотреть diff и снимки; отдельно принять решение о merge/деплое. Production не обновлялся автоматически.
2. Разобрать оставшиеся npm-предупреждения по достижимости и дереву зависимостей. Выполнять совместимые обновления отдельно; major-миграция Tailwind или router не должна менять дизайн попутно.
3. Провести ограниченный ручной dry-run HH с обезличенными результатами; подтверждённый личный вклад уже добавлен. Не использовать статистику offline-тестов как метрику качества найма.
4. Для Telegram → AI → YouGile проверить цикл состояния в n8n и настроить ограничения до тестового запуска. Для AI-суфлёра предоставить исходники и воспроизводимую демонстрацию; остальные заготовки наполнять проверяемыми данными.
5. Подтвердить источники маркетинговых показателей и уточнить `%`/п.п., периоды и потенциальные сделки/выручку.
6. Отдельно исправить исходный lint, добавить quality checks в CI, проверить Safari и системное уменьшение движения; затем при необходимости профилировать canvas.

Новая дизайн-система, переписывание компонентов, CMS, смена хостинга и переработка анимаций для выполнения этой задачи не нужны.
