## Сценарий

Поручение появляется в переписке, но для работы команды его нужно перенести в трекер, сохранить уточнения, срок и связь с обсуждением. Ручной перенос легко теряет контекст, а повторное сообщение создаёт риск дубля.

Пользователь отвечает **/task** на исходное сообщение; после команды может дописать уточнение. Workflow извлекает поручение, проверяет доступ и назначение, ищет уже созданную задачу, затем запрашивает AI и готовит карточку YouGile. Подтверждение или понятная ошибка возвращаются в тот же чат.

## Как работает система

Доступ и возможный дубль проверяются до обращения к модели. Число HTTP-попыток и паузы ограничены, а ошибки настройки отделены от временной недоступности сервиса.

## Архитектура

Экспорт содержит **35 узлов: 32 исполняемых и 3 служебные заметки**. Telegram — точка входа и канал результата. Code-узлы держат состояние и валидируют данные. HTTP Request обращается к YouGile API v2 и OpenAI Chat Completions. Wait и IF образуют циклы повторов. Ключи должны храниться в credentials n8n.

| Компонент | Что получает и возвращает |
|---|---|
| Telegram | message/reply → команда и исходное поручение; обратно — подтверждение/ошибка |
| Code-узлы | JSON item со состоянием `_yg`, `_ai`, `_create`; валидация и маршрутизация |
| HTTP Request | Запрос к API → statusCode, headers и body для обработки |
| IF / Wait | Условие → выход 0/1; задержка → возврат в нужную фазу |

## Инженерный разбор

### Разбор команды и контекста

Принимается `/task`, в том числе адресованный боту, с необязательным уточнением. `/taskforce` не считается командой. Исходный текст берётся из reply, включая caption вложения; служебное сообщение создания forum-темы не подменяет поручение. Сохраняются автор, инициатор и маркер сообщения. При отказе доступа workflow молчит.

### Поиск назначения и дублей — конечный автомат

Состояние `_yg` проходит фазы `boards → columns → dup → done`. Доска и колонка ищутся по точному названию. Пагинация меняет offset; ошибка доступа не маскируется под «доска не найдена». Дубль определяется по маркеру исходного сообщения в description задачи. Если найден, работа завершается до LLM.

### Структура ответа отделена от доверия к нему

Запрос задаёт `response_format: json_schema`, `strict: true`, семь обязательных полей и `additionalProperties: false`. Модель должна сохранять неясности в missing_information, не выдумывать имя или срок и не превращать «до пятницы» в неподтверждённую календарную дату. Строка модели настраивается; успешный вызов конкретной модели не заявляется.

Code-валидатор отдельно проверяет объект, непустые title/description, enum направления/приоритета, строки исполнителя/срока и массив уточнений. Title нормализуется и ограничивается 12 словами, description — 4000 символами. Требование начать title с глагола есть в prompt, но грамматического разбора в коде нет. Запрет лишних полей задаёт схема провайдера; локальный валидатор не является универсальным JSON Schema-движком.

### Повторы и ошибки

Для lookup YouGile предусмотрены до трёх повторов, backoff и Retry-After. AI и создание задачи ограничены тремя попытками; 401/403 не повторяются. 429, 5xx и отсутствие ответа ведут через Wait; после исчерпания лимита — сообщение об ошибке. Невалидный JSON AI также повторяется в пределах лимита: комментарий про один «ремонтный» повтор уже, чем фактическая логика кода.

Создание использует стабильный idempotencyKey из идентичности исходного сообщения. Поиск маркера и ключ запроса — два разных механизма. Успешный HTTP без ID задачи вызывает просьбу проверить доску вручную, а не подтверждение создания.

### Фактический payload

В POST передаются `title`, `columnId`, `description`, `idempotencyKey`. Исполнитель, срок, направление и приоритет сохраняются строками в **description**. Поля назначения исполнителя и дедлайна YouGile автоматически не заполняются. Для этого понадобятся маппинг пользователей, разбор дат и проверка API-контракта.

## Данные и контракты

**Синтетический пример, не рабочая переписка.** Вход: «Подготовить черновик письма о новой функции. Показать редактору до пятницы». Ответ на сообщение: `/task`.

Искусственно заданный ответ LLM прошёл реальный Code-валидатор и сборщик payload при offline-запуске:

```json
{
  "title": "Подготовить черновик письма о новой функции",
  "description": "Подготовить текст и передать редактору на согласование.",
  "direction": "Рассылки",
  "priority": "medium",
  "assignee_name": "",
  "deadline": "до пятницы",
  "missing_information": ["Кто подготовит черновик?"]
}
```

Сборщик добавляет эти сведения в description будущей карточки, вместе с источником, уточнением и маркером. Это **проверка преобразования данных**, не ответ настоящей модели и не созданная задача в трекере.

Псевдокод по workflow, без публикации закрытого листинга:

```text
проверить команду, доступ и исходный текст
найти доску и колонку; проверить маркер дубля
дубль найден → уведомить, завершить
запросить JSON по схеме; проверить поля
невалидно → ограниченный повтор или ошибка
собрать описание и стабильный ключ; POST /tasks
есть ID → подтверждение; нет ID → ручная проверка
```

## Демонстрация

19.10.2026 повторены **32 локальные проверки** исходных Code-узлов на искусственных данных: команда/reply/caption, отказы доступа, JSON и refusal модели, HTTP-ошибки, поиск маркера, idempotencyKey и отсутствие нативного назначения исполнителя.

| Проверенный случай | Полученный результат |
|---|---|
| Валидный reply /task | Путь ok, извлечены поручение и уточнение |
| Чужой пользователь | silent, без ответа |
| Маркер уже есть в задаче | duplicateFound, завершение до AI |
| Битый JSON / refusal | Нет разрешения создавать задачу |
| 401 | Без retry |
| 429 | Backoff с учётом Retry-After |
| Искусственный валидный JSON | Сформирован payload; POST не выполнялся |

Скриншота работающего n8n или карточки YouGile пока нет; схема построена из файла, а не изображает live-выполнение.

## Мой вклад

Постановка личного сценария «поручение → задача» и работа над workflow с AI-инструментами. Доступны реальный экспорт и инструкция настройки: по ним восстановлены логика интеграции и контракты. Подробное авторство каждого Code-узла и личные сквозные запуски не зафиксированы; ручное создание всех 35 узлов не заявляется.

## Бизнес-применение

Подход подходит командам, у которых поручения остаются в мессенджере: перенести их в очередь задач, сохранить источник и перечислить, что нужно уточнить. Архитектура показывает работу с API-контрактами, недоверенным AI-ответом и повторными событиями. Экономия времени и снижение потерь задач пока не измерены.

## Границы и развитие

Экспорт неактивен; проверки выполнены вне n8n с подменёнными ответами узлов. Реальные Telegram/LLM/YouGile API и production не проверялись.

- Обработчики циклов читают `.first()` без runIndex. Возможен возврат к раннему состоянию; offline-воспроизведение выявило потерю фазы. До активации нужна проверка в n8n.
- Пустые allowed_chat_id / allowed_user_ids отключают соответствующее ограничение. Перед тестовой активацией их нужно задать явно.
- Поиск маркера ограничен шестью страницами по 500 задач. Реальная идемпотентность, гонки и неопределённый сетевой ответ требуют интеграционных тестов; обещание из текста ошибки «дубль не появится» пока нельзя считать гарантией.

Следующий шаг — проверить/исправить цикл состояния, затем записать сценарий в тестовой группе: команда → карточка → повтор → ошибка. Развитие — нативный исполнитель и дедлайн после проверки маппинга и API.
