## Задача

Переносить поручения из рабочей переписки в таск-трекер, сохраняя контекст и связь с исходным сообщением. При повторной команде важно проверять, не создавалась ли задача раньше.

## Моё решение

Workflow n8n для сценария **/task в ответ на сообщение**:

**Telegram → проверка доступа и контекста → поиск дубля → LLM и JSON Schema → проверка ответа → YouGile API → подтверждение или ошибка.**

LLM получает поручение и уточнение после команды, выделяет название, описание, направление, приоритет, исполнителя, срок и недостающие сведения. Структура ответа задана JSON Schema и дополнительно проверяется Code-узлом. Для сетевых ошибок, 429 и 5xx предусмотрены ограниченные повторы; ошибки доступа направляются в отдельную ветку.

Используются n8n, Telegram Bot API, LLM, JavaScript и YouGile REST API. Исполнитель, срок и приоритет сохраняются в описании карточки; поля назначения исполнителя и дедлайна YouGile автоматически не заполняются.

## Бизнес-применение

Для маркетинговой команды — единый способ переводить поручения из переписки в понятные задачи с контекстом и списком уточнений. Потенциальная польза — меньше ручного переноса и потерянных деталей; экономия времени пока не измерена.

## Мой вклад

Развиваю персональную автоматизацию сценария «поручение → задача». Доступные материалы проекта — схема workflow и инструкция настройки. Они позволяют показать логику интеграции; подробное распределение авторства Code-узлов и личные live-запуски в этих материалах не зафиксированы.

## Материалы и результат проверки

Обложка показывает процесс интеграции. Реальный экспорт содержит **35 узлов**, включая служебные заметки; инструкция описывает настройку доступа, credentials и тестовый сценарий. Исходные файлы остаются приватными из-за внутренней конфигурации.

Выполнены **32 локальные проверки** Code-узлов на синтетических данных: команда, доступ, JSON, ветки ошибок и подготовка запросов. [Техническая сводка (JSON)](/projects/yougile-workflow-verification.json) фиксирует область проверки.

## Статус и следующий шаг

Workflow-прототип: экспорт неактивен, сквозной запуск и production не подтверждены. До тестового запуска нужно проверить состояние циклов с `.first()`, явно настроить доступ и проверить повторы создания задачи. Поиск дублей ограничен последними 3000 задачами; idempotencyKey предусмотрен запросом и спецификацией API, но живые повторы не проверялись.

Следующий материал — запись в тестовой группе: исходное сообщение → /task → карточка YouGile → повторная команда и обработка ошибки. На ней нужно показать фактический результат без рабочих данных и доступов.
